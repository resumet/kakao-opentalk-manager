# 카카오톡 대화창 MVP — Codex 개발 인수인계 (기준선: v5)

> **현재 구현 버전: v7 (기준선 v5).** v6의 오픈채팅 전용 필터는 실제 환경에서 대화방이 전혀 표시되지 않아 **폐기**했습니다. v7은 v5에서 사용자가 요청한 수동 선택 목록과 순회 입력 기능만 추가한 버전입니다.
>
> 이 문서는 기존 구현을 유지하면서 **Windows + Visual Studio Code + Codex**에서 개발을 계속하기 위한 설명서입니다. 새 기능을 선제적으로 추가하라는 요청이 아닙니다.

## 1. 프로젝트의 목적과 MVP 고정 지침

- **Windows 10/11, x64 전용**, 설치 없이 실행되는 **단일 네이티브 EXE**.
- 외부 프레임워크, Python, .NET, 추가 런타임, 별도 서버가 필요 없어야 함.
- **요청받은 기능만** 구현. 현재 문서화된 목록·버튼·입력창 이외의 설정/검색/자동 새로고침/로그인/백그라운드 기능을 임의로 추가하지 않음.
- 별도 창으로 **열어 둔 카카오톡 PC 대화방**을 대상으로 함. 카카오톡 내부 목록에만 있고 별도 창으로 열지 않은 방은 수집하지 않음.
- 현재 **일반 대화방과 오픈채팅방을 따로 분류하지 않음**. 둘 다 별도 창으로 열리고 기존 탐지 규칙에 부합하면 목록에 포함될 수 있음.
- **선택된 오픈톡방 목록**은 사용자가 수동으로 구성하는 목록의 명칭이며, 프로그램이 오픈채팅 여부를 판별한다는 뜻이 아님.
- `@` → `Enter` → `가나다`는 코드에 고정되어 있으며, 입력 시점이나 문구를 임의로 변경하지 않음.

## 2. 현재 구현되어 있는 사용자 동작

1. 사용자가 PC 카카오톡에서 대화방을 **별도의 창**으로 열어 둠.
2. 프로그램 실행 시 `EnumWindows()`로 현재 열려 있는 카카오톡 대화창을 **한 번만** 수집해 목록으로 표시.
3. 왼쪽 **검색된 카톡창 목록**에서 방을 선택하고 **[선택 →]** 클릭: 해당 항목의 제목과 HWND를 오른쪽 **선택된 오픈톡방 목록**으로 이동.
4. 오른쪽 목록에서 방을 선택하고 **[← 제외]** 클릭: 해당 항목을 검색된 목록으로 되돌림.
5. 두 목록 중 마지막으로 선택한 방에서 **[포커스 이동]** 버튼 클릭: 해당 대화창을 앞으로 가져온 뒤 **메시지 입력 컨트롤**에 커서 포커스를 설정.
6. 두 목록 중 마지막으로 선택한 방에서 **[지정 키 입력]** 버튼 클릭: 입력 컨트롤 포커스를 다시 확인한 뒤 다음을 실제 키 이벤트로 입력.

   ```text
   @
   Enter
   가나다
   ```

   - `@`와 `가나다`: `SendInput()` + `KEYEVENTF_UNICODE`로 문자 입력
   - 중간 `Enter`: `SendInput()` + `VK_RETURN`으로 키다운/키업
   - `@` 입력 후 150ms, `Enter` 후 150ms 대기
   - 마지막 `가나다` 뒤에는 **Enter 없음**
7. **[지정 키 입력]** 클릭 자체가 프로그램으로 포커스를 이동시킬 수 있으므로 입력을 보내기 직전에 선택된 대화창을 재활성화함.
8. 아래 **입력 내용** 칸에 문구를 적고 **[목록에 내용 입력]** 클릭: 선택된 오픈톡방 목록을 위에서 아래로 순회하며 각 방의 입력칸에 같은 문구를 입력.
   - 각 방과 입력 컨트롤을 입력 직전에 다시 검증함.
   - 방 사이에는 150ms를 대기함.
   - 대상이나 포커스 검증이 실패하면 남은 순회를 중단함.
   - 문구 뒤에 Enter를 붙이지 않으므로 자동 발송하지 않음.
   - 단일 행 입력이며 최대 4,095자.

**중요:** `Enter`는 실제 키 입력이므로 카카오톡의 상태에 따라 메시지 전송, 멘션 선택 등 예상하지 못한 동작이 일어날 수 있음. **본인 소유 테스트 대화방에서만 먼저 검증**할 것.

## 5. 현재 소스 구조 (`main.c`)

### 창 목록 확보

- `owned_by_kakaotalk(hwnd)`: `GetWindowThreadProcessId` + `OpenProcess` + `QueryFullProcessImageNameW`로 소유 프로세스 실행 파일 이름이 **`KakaoTalk.exe`**인지 검증.
- `inspect_child(hwnd, ...)`: 자식 창 클래스가 `RichEdit*`, `EVA_VH_ListControl*`, `_EVA_CustomScrollCtrl`에 해당하는지 조사.
- `looks_like_chat_window(hwnd)`: 표시 중이고 제목이 있으며 `KakaoTalk.exe` 소유인 창 중 대화창 관련 컨트롤이 확인되는 창만 인정. 제목이 정확히 `카카오톡`/`KakaoTalk`/`カカオトーク`인 메인 창 제외.
- `collect_window(hwnd, ...)`: 목록에 대화창 제목을 추가하고 `LB_SETITEMDATA`에 **HWND(실제 창 핸들)** 저장. 같은 제목의 서로 다른 창도 별개의 HWND로 다룸.
- 수집 시점: `WM_CREATE`에서 `EnumWindows(collect_window, ...)` **한 번** 호출. 자동 갱신 없음.

### 수동 선택 목록

- `move_selected_room(from, to)`: 선택 항목의 제목과 HWND를 대상 ListBox로 추가한 뒤 원본 ListBox에서 제거. **[선택 →]**과 **[← 제외]**가 같은 함수를 양방향으로 사용.
- `active_listbox`: 두 목록 중 마지막으로 선택한 목록을 기억하여 기존 **[포커스 이동]**, **[지정 키 입력]** 대상 선택을 유지.
- 선택된 오픈톡방 목록은 사용자가 수동으로 구성하며 실제 오픈채팅 여부를 자동 판별하지 않음.

### 포커스 이동

- `selected_chat_window()`: 현재 선택된 목록 항목의 HWND를 꺼내고 아직 유효한 카카오톡 대화창인지 재검증.
- `find_input_child(hwnd, ...)`: 표시 중·사용 가능한 `RichEdit*` 자식 컨트롤 중 **화면상 가장 아래쪽** 후보 선택. 메시지 입력칸이라고 추정하는 휴리스틱이며 100% 보장 아님.
- `focus_chat_input(hwnd)`: 최소화되어 있으면 `SW_RESTORE`, `SetForegroundWindow`, `EnumChildWindows`로 입력칸 탐색, 필요 시 `AttachThreadInput`, `SetFocus`, `GetFocus`로 포커스 설정 및 확인.
- `focus_selected_window()`: [포커스 이동] 버튼의 진입 함수.

### 키 시퀀스

- `send_character(wchar_t)`: 유니코드 문자의 키다운/키업을 `SendInput()`으로 전송.
- `send_enter()`: `VK_RETURN`의 키다운/키업을 전송.
- `type_sequence_to_selected()`: [지정 키 입력] 버튼의 진입 함수. 입력 전 대상 입력칸 포커스 재설정; 각 단계 전 `GetForegroundWindow() == target` 확인; `@` → 150ms → `Enter` → 150ms → `가나다` 순서.
- `type_text_to_chat()`: 지정된 한 방의 입력 컨트롤에 포커스를 설정하고 입력창 문구를 유니코드 키 이벤트로 입력. Enter는 추가하지 않음.
- `type_message_to_selected_rooms()`: 선택된 오픈톡방 목록을 위에서 아래로 순회하며 `type_text_to_chat()` 호출. 방 사이 150ms 대기, 검증 실패 시 전체 순회 중단.
- `window_proc()`: 두 ListBox, 이동·포커스·입력 버튼, 문구 입력창 생성과 클릭 분기, UI 크기 재배치 등 Win32 메시지 처리.
- `app_entry()`: 별도 CRT 시작 코드 없이 자체 Win32 메시지 루프 실행.

## 6. Visual Studio Code에서 프로젝트 시작

1. 제공한 ZIP을 압축 해제하고 **`KakaoMVP_v5_Codex` 폴더 자체를 VS Code로 엽니다**.
2. VS Code의 Codex에 작업을 지시하기 전 `README.md`와 `AGENTS.md`를 확인합니다. Codex는 프로젝트의 `AGENTS.md`를 작업 지침으로 활용할 수 있습니다.
3. **Visual Studio 2022 Build Tools(또는 Visual Studio C++ 데스크톱 개발 도구)**와 **Windows SDK**가 설치된 Windows에서 `x64 Native Tools Command Prompt for VS 2022`를 실행합니다.
4. 해당 명령 프롬프트에서 소스 폴더로 이동한 후 아래 명령을 실행합니다. VS Code 통합 터미널을 쓴다면 `cl`과 SDK `.lib`를 찾을 수 있도록 개발자 도구 환경이 활성화되어 있어야 합니다.

### MSVC 빌드 명령 예시 (Windows x64)

```bat
cl /nologo /O2 /GS- /Zl /utf-8 /TC main.c /link /SUBSYSTEM:WINDOWS /ENTRY:app_entry /NODEFAULTLIB /OUT:KakoMVP-v1.0.exe kernel32.lib user32.lib gdi32.lib
```

- `cl`: Microsoft C/C++ 컴파일러. `where cl`로 사용 가능 여부 확인.
- `/utf-8`: C 소스의 한글 리터럴 보존.
- `/TC`: C 언어로 컴파일.
- `/ENTRY:app_entry`와 `/NODEFAULTLIB`: 원본 v5의 독자 진입점/기본 DLL 의존성을 유지.
- `/GS-`: CRT 없이 독자 진입점을 사용하는 **기존 최소 구현을 재현하기 위한 빌드 옵션**. 스택 보호가 꺼지므로 보안 강화가 필요한 정식 배포 시에는 표준 런타임 시작점 및 보안 설정 재검토 필요.
- **검증 범위:** 이 문서 작성 환경에서는 현행 `main.c`를 `clang-cl` + `lld-link`로 Windows x64 EXE로 재빌드했으며 import DLL이 `kernel32.dll`, `user32.dll`, `gdi32.dll`뿐임을 확인했습니다. 위 **MSVC `cl` 명령 자체는 실제 Windows에서 실행 검증하지 못했으므로** 빌드 오류가 나면 컴파일러·링커 출력에 따라 조정해야 합니다.

### `main.c` 작업상 주의

원본 v5는 **Windows SDK 헤더(`windows.h`)를 사용하지 않고 Win32 자료형, 상수, API import를 직접 선언**합니다. 따라서 단순히 `#include <windows.h>`를 추가하면 중복 선언이 발생할 수 있습니다. 소스 구조를 재설계할 때에만 관련 선언을 일괄 정리하세요. `INPUT` 구조체는 **x64 레이아웃(40바이트)**에 고정되어 있어 32비트용으로 그대로 빌드하면 안 됩니다.

## 8. 알려진 제약 / 개선 전 반드시 확인할 점

- **오픈채팅 여부 미분류:** v6에서 필터 때문에 목록이 사라져 철회. 근거 없는 UI 키워드/추측성 필터를 다시 적용하지 말 것.
- **카카오톡 버전 의존:** `RichEdit*` 등의 창 클래스는 공개되고 안정적으로 유지되는 카카오톡 계약 API가 아님. 카카오톡 업데이트로 탐지/입력 포커스가 달라질 수 있음.
- **대화창 판별 휴리스틱:** `RichEdit*`가 있는 카카오톡 창을 대화방으로 간주하므로 다른 팝업이 포함되거나 채팅방이 누락될 수 있음.
- **키 입력의 부작용:** `@` 이후 `Enter`는 카카오톡 설정·멘션 UI 상태에 따라 메시지 발송 또는 다른 동작을 유발할 수 있음. 안전한 테스트 방에서 확인할 것.
- **Windows 포그라운드/UIPI:** 권한 수준 차이, 포그라운드 잠금, 관리자 권한 등의 조건에 따라 `SetForegroundWindow`, `SetFocus`, `SendInput`가 실패할 수 있음.
- **대상 변경 경합:** 키 입력 사이에 사용자가 포커스를 옮기면 코드가 최대한 입력을 중단하도록 설계되어 있지만, `GetForegroundWindow` 확인과 `SendInput` 사이의 경합을 100% 제거하지는 못함.
- **순회 입력은 발송하지 않음:** 입력창 문구만 각 방 입력칸에 채우며 Enter를 추가하지 않음. 입력 후 내용은 각 카카오톡 대화창에 남음.
- **순회 중단:** 선택 목록의 한 방이라도 닫혔거나 포커스 획득에 실패하면 이후 방은 입력하지 않음. 별도 오류 알림은 없음.
- **입력 길이:** 단일 행 최대 4,095자.
- **상태 알림 없음:** 원래 MVP 지침 때문에 실패 메시지, 새로고침, 로그, 오류 다이얼로그 등을 추가하지 않음.
- **한 번만 목록 수집:** 새 방을 열면 EXE 재실행 필요.
- **코드 서명 없음:** Windows 보안 경고는 발생할 수 있음.

4. **[포커스 이동]**, **[지정 키 입력]**, 시퀀스 `@` → `Enter` → `가나다`를 특별한 지시 없이 변경하지 않습니다.
