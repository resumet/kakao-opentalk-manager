# 카카오톡 대화창 MVP — Codex 개발 인수인계 (기준선: v5)

> **현재 구현 버전: v30 (기준선 v5), 배포 버전: v1.23.** v6의 오픈채팅 전용 필터는 실제 환경에서 대화방이 전혀 표시되지 않아 **폐기**했습니다. v30은 창을 줄일 때 목록·버튼·메시지 설정이 겹치지 않도록 메인 창의 최소 크기를 UI 기준 크기인 1120×820px로 고정한 버전입니다.
>
> 이 문서는 기존 구현을 유지하면서 **Windows + Visual Studio Code + Codex**에서 개발을 계속하기 위한 설명서입니다. 새 기능을 선제적으로 추가하라는 요청이 아닙니다.

## 1. 프로젝트의 목적과 MVP 고정 지침

- **Windows 10/11, x64 전용**, 설치 없이 실행되는 **단일 네이티브 EXE**.
- 외부 프레임워크, Python, .NET, 추가 런타임, 별도 서버가 필요 없어야 함.
- **요청받은 기능만** 구현. 현재 문서화된 목록·버튼·입력창 이외의 설정/검색/자동 새로고침/로그인/백그라운드 기능을 임의로 추가하지 않음.
- 별도 창으로 **열어 둔 카카오톡 PC 대화방**을 대상으로 함. 카카오톡 내부 목록에만 있고 별도 창으로 열지 않은 방은 수집하지 않음.
- 현재 **일반 대화방과 오픈채팅방을 따로 분류하지 않음**. 둘 다 별도 창으로 열리고 기존 탐지 규칙에 부합하면 목록에 포함될 수 있음.
- **선택된 오픈톡방 목록**은 사용자가 수동으로 구성하는 목록의 명칭이며, 프로그램이 오픈채팅 여부를 판별한다는 뜻이 아님.

## 2. 현재 구현되어 있는 사용자 동작

1. 사용자가 PC 카카오톡에서 대화방을 **별도의 창**으로 열어 둠.
2. 프로그램 실행 시 `EnumWindows()`로 현재 열려 있는 카카오톡 대화창을 수집해 목록으로 표시. 검색 목록 상단의 **[다시 불러오기]**를 누르면 선택 목록은 유지한 채 현재 열린 대화창을 재탐지하며, 이미 선택된 HWND는 검색 목록에 중복 표시하지 않음.
3. 양쪽 목록 제목에 현재 항목 수를 `(...개)`로 표시하고 각 항목 사이에 구분선을 그림. 왼쪽 **검색된 카톡창 목록**에서 한 개 이상의 방을 Ctrl/Shift로 선택하고 **[선택 →]**을 클릭하거나 항목을 더블클릭하면 선택된 항목의 제목과 HWND를 오른쪽 **선택된 오픈톡방 목록**으로 이동함.
4. 오른쪽 목록에서도 한 개 이상의 방을 Ctrl/Shift로 선택하고 **[← 제외]**를 클릭하거나 항목을 더블클릭하면 선택된 항목을 검색된 목록으로 되돌리며 양쪽 개수를 갱신함.
5. 오른쪽 **메시지 설정** 영역에서 이미지와 메시지를 준비하고 **[목록에 내용 입력]** 클릭: 선택된 오픈톡방 목록을 위에서 아래로 순회하며 같은 설정을 적용.
   - 클립보드 이미지 영역을 클릭한 뒤 `Ctrl+V`를 누르거나 **[이미지 붙여넣기]**를 누르면 현재 클립보드의 `CF_DIB`, `CF_DIBV5` 또는 PNG 이미지를 앱 메모리에 복사해 보관함. `CF_DIB`/`CF_DIBV5` 이미지는 원본 비율을 유지한 실제 미리보기로 표시함.
   - **[이미지 지우기]**는 앱에 보관된 이미지를 제거하고 미리보기 영역을 **이미지 없음** 표시로 복원함.
   - 저장된 이미지가 없으면 메시지만 입력하며, **[메시지 전송완료하기]**를 체크하지 않은 경우 마지막 Enter를 추가하지 않음.
   - 저장된 이미지가 있으면 각 방에서 이미지를 클립보드에 복원한 뒤 `Ctrl+V` → 기본 1000ms 대기 → 전경 창이 대상 방이 직접 소유하고 같은 `KakaoTalk.exe` 프로세스에 속한 이미지 전송 팝업인지 확인 → 팝업 가로 중앙·하단 25px 지점의 **전송** 영역 클릭 → 사용자 커서 위치 복원 → 기본 1000ms 대기 → 전체 멘션의 `@` 또는 메시지 입력 순서로 처리함.
   - 이미지 전송 팝업은 제목과 전송 버튼 HWND/UI Automation 요소를 노출하지 않고 원래 대화창을 비활성화함. 팝업이 없는 기존 화면에서는 대화창 가로 중앙·창 높이 78%를 사용함. 이미지 전송 단계에서는 Enter를 입력하지 않으며, 이미지 뒤에 입력한 메시지는 **[메시지 전송완료하기]** 선택에 따라 전송함.
   - 각 방과 입력 컨트롤을 입력 직전에 다시 검증하고, 한 방 처리를 마친 뒤 기본 1500ms를 대기하고 다음 방으로 이동함.
   - 대상, 클립보드 또는 포커스 검증이 실패하면 남은 순회를 중단함.
   - 메시지는 여러 줄이며 최대 4,095자. 줄바꿈은 채팅 입력칸에서 메시지를 바로 보내지 않도록 `Shift+Enter`로 입력함. 이미지만 설정한 상태로도 실행할 수 있음.
   - 메시지 작성 영역은 **메시지 작성 미리보기** 제목과 둥근 흰색 카드 안의 여러 줄 입력창으로 표시함. 입력창은 카드의 실제 자식이며 카드 여백을 클릭해도 입력창으로 포커스를 전달함. 목록 영역 폭을 줄여 오른쪽 설정 영역을 넓히고 기본 창과 카드 높이를 늘려 더 많은 메시지를 한 번에 표시함.
   - **[모두를 멘션하기]**가 체크되면 각 방에서 `@` → 기본 500ms 대기 → 실제 `Enter` → 기본 500ms 대기 → 메시지 입력 순서로 처리함. 메시지 뒤의 Enter 여부는 **[메시지 전송완료하기]** 선택에 따름.
   - **[메시지 전송완료하기]**가 체크되고 메시지가 비어 있지 않으면 각 방에서 메시지 입력을 마친 직후 실제 `Enter`를 한 번 보내 전송까지 완료함. 체크하지 않으면 기존처럼 메시지가 입력칸에 남음.
   - 메인 화면의 시간 설정 버튼은 제거됨. **설정 → 옵션**에서 이미지 처리 2개, 전체 멘션 2개, 다음 방 이동 1개까지 총 5개 대기값을 각각 0~600000ms로 설정할 수 있으며 **[저장하기]**를 누르면 현재 실행에 값을 저장하고 옵션 창을 닫음.
6. 메인 창 하단의 **진행 로그**에 다음 결과를 실행 순서대로 누적 표시.
   - 카카오톡 대화창 탐지 완료
   - 선택 목록 추가·제외
   - 목록 입력 시작, 방별 진행·성공·실패, 설정된 다음 방 대기 및 전체 완료
   - 이미지·메시지·전체 멘션 설정이 모두 없거나 선택된 방이 없을 때의 중단 사유
7. UI는 EXE 리소스에 포함된 Pretendard Regular/SemiBold 글꼴, 밝은 중성 배경, 굵은 구획 제목, 둥근 평면 버튼과 주요 작업의 파란색 강조를 사용함. 실행 시 글꼴을 프로세스 전용으로 등록하므로 별도 설치가 필요 없음.
8. 메인 창은 UI가 겹치거나 잘리지 않는 1120×820px을 최소 크기로 사용하며, 그보다 크게 조절하면 목록·메시지 카드·로그가 창 크기에 맞춰 확장됨.
9. 메인 창 제목에 **비즈업클래스-카카오단톡 메시지 자동화 (v1.23)**를 표시하고 메뉴에서 다음 기능을 제공함.
   - **설정 → 옵션**: 5개 대기값을 변경하고 저장하는 시간 설정 창을 엶.
   - **도움말 → 업데이트 확인**: GitHub의 최신 Release 주소를 WinHTTP로 확인해 현재 버전과 비교하고, 새 버전이 있으면 기본 브라우저로 다운로드 페이지를 열 수 있음.
   - **도움말 → 프로그램 정보**: 프로그램명, v1.23 버전 및 Windows x64 단독 실행형 정보를 표시함.

**중요:** 전체 멘션의 `Enter`, **[메시지 전송완료하기]**의 마지막 `Enter`, 이미지 확인창의 **전송** 버튼 클릭은 실제 동작이므로 메시지·이미지가 전송될 수 있음. **본인 소유 테스트 대화방에서만 먼저 검증**할 것.

### 2026-10-24 standalone EXE 생성 기록

- v5 `main.c`를 변경하지 않고 Windows x64 GUI 실행 파일 `KakaoMVP.exe`를 생성함.
- LLVM 23.1.4의 `clang-cl`과 `lld-link`를 사용했으며 CRT 및 추가 런타임을 링크하지 않음.
- PE 검사 결과: `COFF-x86-64`, `IMAGE_SUBSYSTEM_WINDOWS_GUI`.
- import DLL: `KERNEL32.dll`, `USER32.dll`, `GDI32.dll`만 확인됨.
- 실행 파일 SHA-256: `7623509dbae9ef89064bf623ff58b20b9c4fb387fdd96db816d2943bf81d4fbf`
- 실행 직후 2초간 프로세스가 정상 유지되는 시작 점검을 통과함.

2. 소스와 문서를 커밋하여 `main`에 푸시함.
3. 저장소 루트의 PowerShell에서 같은 버전으로 아래 명령을 한 번 실행함.


1. 태그 시점의 소스를 체크아웃하고 README/AGENTS 버전 일치를 검사함.
2. GitHub Windows runner의 Visual Studio C++ x64 도구와 Windows SDK로 `KakoMVP-v1.23.exe`를 빌드함.
3. 결과가 x64 PE32+ Windows GUI 실행 파일인지 검사하고 SHA-256 파일을 생성함.
4. `KakoMVP v1.23` GitHub Release를 만들고 EXE 및 `KakoMVP-v1.23.exe.sha256.txt`를 첨부함.

태그가 이미 있거나 작업 트리에 미커밋 변경이 있거나 `main`이 원격과 다르면 스크립트는 새 태그를 만들지 않습니다. 자동 실행이 실패하면 GitHub **Actions → Build and publish Windows release → Run workflow**에서 기존 태그를 입력해 다시 실행할 수 있습니다.

## 5. 현재 소스 구조 (`main.c`)

### 창 목록 확보

- `owned_by_kakaotalk(hwnd)`: `GetWindowThreadProcessId` + `OpenProcess` + `QueryFullProcessImageNameW`로 소유 프로세스 실행 파일 이름이 **`KakaoTalk.exe`**인지 검증.
- `inspect_child(hwnd, ...)`: 자식 창 클래스가 `RichEdit*`, `EVA_VH_ListControl*`, `_EVA_CustomScrollCtrl`에 해당하는지 조사.
- `looks_like_chat_window(hwnd)`: 표시 중이고 제목이 있으며 `KakaoTalk.exe` 소유인 창 중 대화창 관련 컨트롤이 확인되는 창만 인정. 제목이 정확히 `카카오톡`/`KakaoTalk`/`カカオトーク`인 메인 창 제외.
- `collect_window(hwnd, ...)`: 목록에 대화창 제목을 추가하고 `LB_SETITEMDATA`에 **HWND(실제 창 핸들)** 저장. 같은 제목의 서로 다른 창도 별개의 HWND로 다루며 선택 목록에 이미 있는 HWND는 검색 목록 재수집에서 제외함.
- 수집 시점: `WM_CREATE`에서 처음 호출하고 사용자가 **[다시 불러오기]**를 누를 때 검색 목록을 비운 뒤 다시 호출. 자동 갱신은 하지 않음.
- `reload_chat_windows()`: 검색 목록만 초기화해 다시 수집하고 양쪽 개수 제목과 진행 로그를 갱신함.
- `draw_room_list_item()`: owner-draw 목록 항목의 선택 배경, 말줄임 제목, 포커스와 하단 구분선을 그림.

### 수동 선택 목록

- 두 ListBox에 `LBS_EXTENDEDSEL`을 적용하여 Ctrl/Shift 다중 선택을 지원함.
- `move_selected_rooms(from, to)`: 선택된 모든 항목의 제목과 HWND를 대상 ListBox에 원래 순서대로 추가한 뒤 원본 ListBox에서 뒤쪽 인덱스부터 제거하고 양쪽 제목의 개수를 갱신. **[선택 →]**, **[← 제외]**, 양쪽 목록 더블클릭이 같은 함수를 양방향으로 사용함.
- 선택된 오픈톡방 목록은 사용자가 수동으로 구성하며 실제 오픈채팅 여부를 자동 판별하지 않음.

### 입력 대상 포커스 검증

- `find_input_child(hwnd, ...)`: 표시 중·사용 가능한 `RichEdit*` 자식 컨트롤 중 **화면상 가장 아래쪽** 후보 선택. 메시지 입력칸이라고 추정하는 휴리스틱이며 100% 보장 아님.
- `focus_chat_input(hwnd)`: 최소화되어 있으면 `SW_RESTORE`하고 입력칸을 탐색한 뒤, 현재 전경 창과 대상 RichEdit의 입력 스레드를 필요한 범위에서 `AttachThreadInput`으로 연결. 연결 상태에서 `SetForegroundWindow`, `SetFocus`, `GetFocus`로 전경·포커스를 설정 및 확인하고 연결을 해제함.

### 메시지 설정과 이미지 클립보드

- `capture_clipboard_image()`: 현재 클립보드에서 `CF_DIB`, `CF_DIBV5`, PNG 순으로 지원 이미지를 찾아 독립된 전역 메모리에 복제.
- `image_preview_proc()`: 클릭 시 키보드 포커스를 받고 `Ctrl+V`를 기존 클립보드 이미지 저장 경로로 전달하며, 저장된 DIB 이미지의 헤더와 픽셀 위치를 검증해 원본 비율로 미리보기 영역에 그림.
- `message_card_proc()`: 밝은 테두리와 둥근 흰색 카드 배경을 그리고, 카드 여백 클릭을 자식 메시지 Edit의 포커스로 전달함. 메시지 Edit는 카드의 `WS_CLIPCHILDREN` 영역 안에서 그려짐.
- `publish_stored_image()`: 저장된 이미지 메모리를 다시 복제하여 시스템 클립보드에 게시. 각 방 처리 시 클립보드 내용은 저장 이미지로 교체됨.
- `clear_stored_image()`: 저장 이미지를 해제하고 오른쪽 상태 표시를 **이미지 없음**으로 변경.
- `send_paste()`: `SendInput()`으로 실제 `Ctrl+V` 키다운·키업을 전송하고 실패 시 Ctrl 키를 해제.
- `click_image_send_overlay()`: 대상 방이 소유한 같은 프로세스의 전경 이미지 전송 팝업을 검증하고 팝업 가로 중앙·하단 25px의 **전송** 영역을 실제 왼쪽 마우스 입력으로 클릭한 뒤 사용자 커서를 복원. 별도 팝업이 없는 기존 화면에서는 대상 방 가로 중앙·전체 높이 78%를 사용.

### 화면 스타일

- `app_entry()`: EXE의 RCDATA에 포함된 Pretendard Regular/SemiBold를 `AddFontMemResourceEx()`로 프로세스 전용 등록하고 `Pretendard`를 일반 본문과 굵은 구획 제목에 적용. 리소스 등록이 실패한 경우에만 Segoe UI로 대체함.
- `app_font`/`section_font`: Pretendard의 400/600 두께를 각각 일반 본문과 구획 제목에 적용함.
- `draw_modern_button()`: Win32 owner-draw로 둥근 평면 버튼, 눌림·비활성·키보드 포커스 상태와 주요 작업의 파란색 강조를 그림.
- `WM_ERASEBKGND`와 `WM_CTLCOLOR*`: 밝은 중성 배경과 흰색 목록·입력·로그 표면을 표시함.

### 메시지 입력 시퀀스

- `send_character(wchar_t)`: 유니코드 문자의 키다운/키업을 `SendInput()`으로 전송.
- `send_enter()`: `VK_RETURN`의 키다운/키업을 전송.
- `send_shift_enter()`: 여러 줄 메시지의 줄바꿈을 위해 Shift 키와 Enter 키의 다운/업을 순서대로 전송하고 일부 입력 실패 시 두 키를 해제함.
- `type_content_to_chat()`: 지정된 방에 저장 이미지를 클립보드로 게시해 붙여넣고 설정된 시간 후 확인창의 **전송** 버튼으로 전송함. 다시 설정된 시간을 기다린 뒤 입력칸을 활성화하고, 전체 멘션 선택 시 `@` → 설정 시간 → `Enter` → 설정 시간 → 메시지 순서로 입력함. 여러 줄 메시지는 줄바꿈마다 `Shift+Enter`를 사용하며 **[메시지 전송완료하기]**가 체크되고 메시지가 비어 있지 않을 때만 마지막 Enter를 전송함.
- `type_message_to_selected_rooms()`: 선택된 오픈톡방 목록을 위에서 아래로 순회하며 `type_content_to_chat()` 호출. 한 방 처리 완료 후 설정된 시간만큼 대기하고, 검증 실패 시 전체 순회를 중단함.
- `append_log()`: 읽기 전용 로그 Edit 컨트롤의 끝에 상태 문구를 추가하고 최신 항목으로 스크롤.
- `create_app_menu()`: 설정 메뉴의 **옵션**과 도움말 메뉴의 **업데이트 확인**·**프로그램 정보** 명령을 생성함.
- `fetch_latest_version()`/`check_for_updates()`: 사용자 요청 시 WinHTTP의 HTTPS 요청과 자동 리디렉션 최종 URL에서 최신 Release 태그를 읽고 현재 버전과 비교하며, 새 버전이면 `ShellExecuteW()`로 최신 Release 페이지를 엶.
- `show_program_information()`: 현재 프로그램명, v1.23 버전, 지원 실행 환경을 대화상자로 표시함.
- `window_proc()`: 두 ListBox, 목록 이동 버튼, 이미지·메시지 설정, 전체 멘션과 메시지 전송 완료 체크박스, 시간 설정, 프로그램 메뉴, 진행 로그 생성과 클릭 분기, UI 크기 재배치 등 Win32 메시지 처리.
- `app_entry()`: 내장 글꼴 등록 후 별도 CRT 시작 코드 없이 자체 Win32 메시지 루프 실행.

### 시간 설정

- `TimingSettings`: 이미지 처리 2개, 전체 멘션 2개, 다음 방 이동 1개의 `Sleep()` 값을 개별 `DWORD` 설정으로 보관하며 기본값은 `1000/1000/500/500/1500ms`임.
- `timing_window_proc()`: 옵션 창의 5개 숫자 입력창과 **[저장하기]** 버튼을 처리함. 모든 값이 0~600000ms 정수일 때 현재 실행에 저장하고 창을 닫으며, 오류가 있으면 문구를 표시하고 창을 유지함.
- `show_timing_settings()`: 시간 설정 창을 한 개만 생성하거나 기존 창을 다시 앞으로 가져옴. 설정 파일을 만들지 않으므로 앱을 다시 실행하면 기본값으로 돌아감.

## 6. Visual Studio Code에서 프로젝트 시작

1. 제공한 ZIP을 압축 해제하고 **`KakaoMVP_v5_Codex` 폴더 자체를 VS Code로 엽니다**.
2. VS Code의 Codex에 작업을 지시하기 전 `README.md`와 `AGENTS.md`를 확인합니다. Codex는 프로젝트의 `AGENTS.md`를 작업 지침으로 활용할 수 있습니다.
3. **Visual Studio 2022 Build Tools(또는 Visual Studio C++ 데스크톱 개발 도구)**와 **Windows SDK**가 설치된 Windows에서 `x64 Native Tools Command Prompt for VS 2022`를 실행합니다.
4. 해당 명령 프롬프트에서 소스 폴더로 이동한 후 아래 명령을 실행합니다. VS Code 통합 터미널을 쓴다면 `cl`과 SDK `.lib`를 찾을 수 있도록 개발자 도구 환경이 활성화되어 있어야 합니다.

### MSVC 빌드 명령 예시 (Windows x64)

```bat
rc /nologo /fo resources.res resources.rc
cl /nologo /c /O2 /GS- /Zl /utf-8 /TC main.c /Fo:main.obj
cl /nologo /c /Od /Oi- /GS- /Zl /TC crt_shim.c /Fo:crt_shim.obj
link /nologo main.obj crt_shim.obj resources.res /SUBSYSTEM:WINDOWS /ENTRY:app_entry /NODEFAULTLIB /OUT:KakoMVP-v1.23.exe kernel32.lib user32.lib gdi32.lib winhttp.lib shell32.lib
```

- `cl`: Microsoft C/C++ 컴파일러. `where cl`로 사용 가능 여부 확인.
- `/utf-8`: C 소스의 한글 리터럴 보존.
- `/TC`: C 언어로 컴파일.
- `rc`: `resources.rc`와 `assets`의 Pretendard TTF 2개를 EXE 리소스로 컴파일. 실행 시 외부 TTF 파일은 필요하지 않음.
- `/ENTRY:app_entry`와 `/NODEFAULTLIB`: 원본 v5의 독자 진입점/기본 DLL 의존성을 유지.
- `crt_shim.c`: `/O2`로 컴파일된 `main.c`가 MSVC에서 요구하는 `memset` 심볼만 제공함. `/Od /Oi-`로 별도 컴파일하여 구현 자체가 다시 CRT 호출로 치환되지 않도록 함.
- `winhttp.lib`/`shell32.lib`: 사용자가 메뉴에서 업데이트 확인을 선택했을 때 GitHub 최신 Release를 확인하고 브라우저를 여는 Windows 기본 시스템 API에 사용함. 별도 런타임이나 설치 파일을 추가하지 않음.
- `/GS-`: CRT 없이 독자 진입점을 사용하는 **기존 최소 구현을 재현하기 위한 빌드 옵션**. 스택 보호가 꺼지므로 보안 강화가 필요한 정식 배포 시에는 표준 런타임 시작점 및 보안 설정 재검토 필요.
- **검증 범위:** v1.23은 기존 `kernel32.dll`, `user32.dll`, `gdi32.dll`과 업데이트 확인에 사용하는 Windows 기본 `winhttp.dll`, `shell32.dll`만 링크합니다. GitHub Windows runner의 MSVC 빌드와 PE 형식 검사 결과는 GitHub Release 자동화 기록에 별도로 반영합니다.

### `main.c` 작업상 주의

원본 v5는 **Windows SDK 헤더(`windows.h`)를 사용하지 않고 Win32 자료형, 상수, API import를 직접 선언**합니다. 따라서 단순히 `#include <windows.h>`를 추가하면 중복 선언이 발생할 수 있습니다. 소스 구조를 재설계할 때에만 관련 선언을 일괄 정리하세요. `INPUT` 구조체는 **x64 레이아웃(40바이트)**에 고정되어 있어 32비트용으로 그대로 빌드하면 안 됩니다.

| T37 | 기본 크기로 프로그램 실행 후 영역 크기 확인 | 창 높이가 820px이고 목록 폭이 이전보다 줄며 메시지 설정 폭과 메시지 입력 높이가 늘어남 |
| T38 | 검색 목록에 항목이 있는 기본 크기 화면 확인 | 검색 목록 제목과 `(...개)`가 잘리지 않고 표시되며 **[다시 불러오기]**가 제목 아래 줄에 표시되고 목록과 겹치지 않음 |
| T39 | 창 가장자리를 1120×820px보다 작게 드래그하거나 API로 축소 시도 | 창 크기가 1120×820px 아래로 줄지 않아 목록·버튼·메시지 설정·로그가 겹치지 않음 |
| T40 | 창을 1120×820px보다 크게 확대한 뒤 UI 확인 | 두 목록, 메시지 카드와 로그가 기존 배치 규칙에 따라 확장되고 서로 겹치지 않음 |

**실제 Windows + 카카오톡 테스트 대화방에서의 이미지 전송, 전체 멘션 선택, 여러 줄 메시지 입력 및 시간 설정 검증은 이 대화에서 수행되지 않았습니다.** Windows 실행 파일 생성, Pretendard 적용, 합성 `KakaoTalk.exe` 대화창의 설정 시간·이미지·멘션·여러 줄 키 순서는 확인했지만 실제 카카오톡에서의 성공을 뜻하지 않습니다.

## 8. 알려진 제약 / 개선 전 반드시 확인할 점

- **오픈채팅 여부 미분류:** v6에서 필터 때문에 목록이 사라져 철회. 근거 없는 UI 키워드/추측성 필터를 다시 적용하지 말 것.
- **카카오톡 버전 의존:** `RichEdit*` 등의 창 클래스는 공개되고 안정적으로 유지되는 카카오톡 계약 API가 아님. 카카오톡 업데이트로 탐지/입력 포커스가 달라질 수 있음.
- **대화창 판별 휴리스틱:** `RichEdit*`가 있는 카카오톡 창을 대화방으로 간주하므로 다른 팝업이 포함되거나 채팅방이 누락될 수 있음.
- **전송 동작의 부작용:** 전체 멘션의 `@` 이후 `Enter`, **[메시지 전송완료하기]**의 마지막 `Enter`, 이미지 확인창의 **전송** 버튼 클릭은 실제 동작이며 메시지 또는 이미지를 전송할 수 있음. 안전한 테스트 방에서 확인할 것.
- **전체 멘션 동작:** 체크박스를 켜면 각 방에서 `@` 뒤 실제 Enter를 누르므로 카카오톡 UI 상태에 따라 멘션을 선택하거나 메시지를 전송할 수 있음. 실제 사용 전 본인 소유 테스트 방에서 확인할 것.
- **이미지 팝업 배치 의존:** **전송** 버튼이 HWND/UI Automation 요소로 노출되지 않아 검증된 이미지 전송 팝업의 가로 중앙·하단 25px를 클릭함. 카카오톡 업데이트로 팝업 배치가 달라지면 다른 영역을 누를 수 있으므로 실제 사용 전 본인 소유 테스트 방에서 확인해야 함. 전경 창이 대상 방 소유가 아니거나 다른 프로세스이거나 팝업 경계가 대상 방 밖이면 클릭하지 않고 중단함.
- **Windows 포그라운드/UIPI:** 권한 수준 차이, 포그라운드 잠금, 관리자 권한 등의 조건에 따라 `SetForegroundWindow`, `SetFocus`, `SendInput`가 실패할 수 있음.
- **대상 변경 경합:** 키 입력 사이에 사용자가 포커스를 옮기면 코드가 최대한 입력을 중단하도록 설계되어 있지만, `GetForegroundWindow` 확인과 `SendInput` 사이의 경합을 100% 제거하지는 못함.
- **이미지와 메시지의 전송 차이:** 저장 이미지는 확인창의 **전송** 버튼을 클릭해 전송함. 뒤이어 입력하는 메시지는 **[메시지 전송완료하기]**가 체크된 경우에만 마지막 Enter로 전송하고, 체크하지 않으면 각 대화방 입력칸에 남음.
- **클립보드 변경:** 이미지 순회 중 시스템 클립보드 내용은 앱에 저장된 이미지로 교체되고 마지막 처리 후에도 이미지가 남음.
- **이미지 형식:** `CF_DIB`, `CF_DIBV5`, PNG 클립보드 형식을 전송용으로 저장하며, 다른 형식만 제공하는 앱에서 복사한 이미지는 저장하지 못할 수 있음. 실제 미리보기 렌더링은 `CF_DIB`/`CF_DIBV5` 형식에 적용되고 PNG 형식만 있는 경우에는 저장 상태만 표시함.
- **순회 중단:** 선택 목록의 한 방이라도 닫혔거나 포커스 획득에 실패하면 이후 방은 입력하지 않고 중단 사유를 진행 로그에 기록함.
- **다중 선택 방식:** 양쪽 목록은 Windows 표준 확장 선택을 사용하므로 연속 범위는 Shift, 개별 항목 추가·해제는 Ctrl과 함께 선택함. 더블클릭하면 현재 선택된 항목 전체가 이동함.
- **입력 길이:** 여러 줄을 포함해 최대 4,095자.
- **시간 설정 보존:** 5개 대기값은 현재 실행 메모리에만 적용되며 앱을 종료하면 기본값으로 돌아감. 허용 범위는 각 0~600000ms임.
- **로그 보존 범위:** 진행 로그는 현재 실행 중에만 화면에 누적되며 파일로 저장하지 않음.
- **내장 글꼴 크기와 라이선스:** Pretendard Regular/SemiBold TTF를 EXE에 포함하므로 실행 파일 크기가 증가함. 글꼴은 SIL Open Font License 1.1에 따라 사용하며 `LICENSE-Pretendard.txt`를 함께 보관함.
- **업데이트 확인 네트워크:** 메뉴를 선택한 경우에만 `github.com`의 최신 Release 주소에 HTTPS로 연결함. 네트워크·프록시·방화벽 문제나 GitHub 장애가 있으면 실패 대화상자와 로그를 표시하며 기존 메시지 기능에는 영향을 주지 않음.
- **고정 밝은 테마:** v1.23의 현대화 색상은 Win32로 그리는 고정 밝은 테마이며 Windows 다크 모드에 자동 전환되지 않음.
- **최소 창 크기:** UI 겹침을 막기 위해 메인 창은 1120×820px보다 작게 줄일 수 없음. 디스플레이 작업 영역이 이보다 작은 환경에서는 화면 일부가 가려질 수 있음.
- **수동 목록 갱신:** 새 방을 연 뒤 **[다시 불러오기]**를 눌러야 검색 목록에 반영되며 자동 갱신하지 않음.
- **코드 서명 없음:** Windows 보안 경고는 발생할 수 있음.

## 9. 이후 Codex 작업을 위한 기본 규칙

1. v5를 기준선으로 유지하되, 이 폴더의 현행 `main.c`를 승인된 변경의 단일 진실의 원천(source of truth)으로 취급합니다.
2. 요청받은 기능 외에는 UI나 자동화를 확장하지 않습니다.
3. 기능 수정 시 변경 함수와 그 변경이 미치는 입력·포커스 흐름을 점검합니다.
4. 제거된 **[포커스 이동]**, **[지정 키 입력]** 버튼과 고정 `@` → `Enter` → `가나다` 기능을 특별한 지시 없이 복원하지 않습니다.
5. **오픈채팅 전용 필터는 다시 적용하지 않습니다.** 명확히 요청받고 실제 Windows 카카오톡 UI 근거가 확보된 경우에만 재설계합니다.
6. 선택된 오픈톡방 목록은 수동 분류이며, 메시지 발송 Enter는 **[메시지 전송완료하기]**가 체크된 경우에만 추가합니다.
7. Windows x64 단독 EXE, 유니코드 한글 입력, 추가 런타임 불필요라는 조건을 유지합니다.
8. 수정 후 Windows에서 빌드하고 T1–T40 중 영향받는 항목을 검증한 다음 `README.md`에 버전/변경사항/검증 결과를 기록합니다. 실제 테스트하지 않았다면 **미검증**이라고 명시합니다.
